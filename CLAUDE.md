# Brandco Landing — правила проєкту

Це портфоліо-лендінг брендингової агенції. Дизайн у Figma:
https://www.figma.com/design/NkSAJbCElSxupag9JPARDD/Branding-agency-website

Читай цей файл на початку кожної сесії й дотримуйся правил нижче для ВСІХ секцій, незалежно від того, в якій розмові їх створюють.

## Стек

- Чистий HTML5 + CSS3 + JS, без build-інструментів, без npm
- GSAP + ScrollTrigger через CDN
- **Desktop-first**: базові стилі під 1440px. Адаптація під мобільний/планшет — окремий етап пізніше, поки що не потрібна (лишай порожні `@media` з `/* TODO */`)

## Структура файлів (не створюй дублікатів, використовуй ці)

```
/index.html
/css/variables.css   ← ВСІ дизайн-токени тут, більше ніде
/css/styles.css
/js/script.js
/assets/images/
/assets/fonts/
```

## Дизайн-токени (джерело правди — css/variables.css)

Кольори:
- `--color-text-primary: #F5F5F0`
- `--color-text-secondary: #8F8F8F`
- фон — майже чорний (звір точне значення з Figma для кожної секції)

Шрифти:
- `--font-heading`: PP Neue Montreal (ваги: Extrabold 800, Bold 700, Semibold 600) — для великих заголовків і лого
- `--font-mono`: IBM Plex Mono — для навігації, лейблів у форматі `[ label ]`, завжди uppercase
- `--font-body`: Inter Regular — для основного тексту

Шрифтові файли лежать у `assets/fonts/`, підключені через `@font-face` з `font-display: swap`.

**Правило:** ЖОДНИХ хардкод-кольорів, розмірів шрифтів чи відступів прямо в styles.css — тільки через змінні з variables.css. Якщо потрібен новий токен — додай його у variables.css, а не пиши значення напряму.

## Конвенції анімацій (GSAP)

- Easing за замовчуванням: `power2.out`
- Тривалість появи елементів: 0.4–0.8s
- Stagger між елементами, що з'являються по черзі: 0.1–0.15s
- Вхідна анімація тексту: fade + translateY (знизу вгору), НЕ ефект друкарської машинки
- Для елементів, що з'являються при скролі — ScrollTrigger з `once: true`
- Значення тривалості/easing виносити константами на початку script.js, не хардкодити в кожній анімації окремо
- **Обов'язково** для кожної анімації: fallback на `prefers-reduced-motion: reduce` — якщо ввімкнено, показувати контент одразу без руху

## Структура сторінки — ОДИН файл, не фрагменти

Весь лендінг — це один-єдиний `index.html`, у якому секції йдуть одна під одною зверху вниз. НІКОЛИ не створюй окремий .html файл для секції, не роби "демо"-версію окремо — кожна нова секція додається прямо у наявний `index.html`, перед `</body>`.

Порядок секцій (дотримуйся саме такого):
1. Header
2. Hero (заголовок + місяць)
3. About us (заголовок "We are a branding agency..." + статистика 120+/+64%/+18/+7)
4. Services
5. Process
6. Cases
7. Team
8. Reviews
9. Footer

Якщо в index.html вже є частина секцій — не переписуй і не видаляй існуючі, просто додай нову в правильне місце за цим порядком.



## Правило про розміри

Ніколи не змінюй font-size, width, height, padding, margin чи gap "заодно" під час виправлення іншої проблеми (анімації, фону тощо), навіть якщо здається, що так "виглядає краще". Якщо для виправлення дійсно необхідно змінити розмір елемента — обов'язково повідом про це окремо і поясни причину, перш ніж застосовувати зміну.

## Правило про спільний фон і динамічний контент

Секції зі спільним фоном (sections-bg, "Bg-all") позиціонуються через position: absolute з фіксованими координатами — це підходить ТІЛЬКИ для чисто статичних секцій, де кількість/висота контенту завжди однакова (Hero, About us).

Будь-яка секція з динамічним контентом, що може змінювати висоту (фільтри як у Cases, акордеони як у Services, будь-які списки, що можуть коротшати чи довшати) — НЕ повинна бути "прибита" до спільного фонового зображення через position: absolute. Замість цього:
- Витягни точний колір фону в цьому місці зі спільної картинки
- Постав його як звичайний background-color на секції
- Тримай секцію в нормальному document flow, щоб висота природно підлаштовувалась під реальний контент

Якщо не впевнений, чи секція буде мати змінну висоту — питай, перш ніж прив'язувати її до спільного фону.

## Іменування класів

Формат `.section__element` (наприклад `.hero__title`, `.stat__value`) — дотримуйся цього патерну в нових секціях, а не вигадуй новий стиль іменування.

## Робота з Figma

Для кожної нової секції:
1. Візьми точні node-id з Figma-посилання вище
2. Витягни реальні кольори/шрифти/тексти через get_design_context — не вгадуй значення
3. Якщо потрібен окремий графічний елемент (як місяць) — уточни в мене, чи є вже вирізаний PNG з прозорим фоном в assets/images/
